## Methodology

Standard js-framework-benchmark keyed operations. Each op: unmeasured prep,
then one measured `click()`, timed in-page from just before the synchronous
click dispatch. **total** stops in a double `requestAnimationFrame` after it
(script + style + layout + frame commit). **script only** stops as soon as
the click task and all microtasks it queued have run (a MessageChannel
message posted right after the click, or the next frame if the browser renders
first), before style and layout. Both come from the same click. DOM state is
asserted at the script stop point and again after the frame, on every sample.
Throttled tables apply `Emulation.setCPUThrottlingRate` (CDP) around each
measured click only; prep runs unthrottled.

## Caveats — read before quoting these numbers

- This is NOT the official js-framework-benchmark harness: in-page timing
  instead of CDP timeline tracing (excludes raster/composite), one uniform
  throttle rate for every op (the official harness picks 1x-16x per op), and
  far fewer samples. Use it for relative ordering, not cross-publication
  comparison.
- The double-rAF total carries a frame-scheduling floor of roughly 8-10ms on
  every op, identical for all frameworks, which compresses cheap-op ratios
  toward 1. The script-only table has no frame floor: use it to compare
  framework work on select/swap/remove/update, where totals are mostly floor.
- Script-only excludes style recalculation, layout and paint, which the
  framework does not control directly but does cause (e.g. by touching more
  nodes than needed). Read it together with the total, never instead of it.
- Script-only is at the 5us resolution of a cross-origin-isolated page;
  sub-0.1ms values and their vs-vanilla ratios (floored at 0.05ms) are noisy.
  `stoppedByFrame` in results.json counts samples where the browser rendered
  before the probe message arrived (the clock then stopped at the frame).
- CDP CPU throttling does not slow sub-millisecond work evenly (vanilla
  select/swap script times barely change at 4x): throttled script times are
  meaningful for ops that take milliseconds, noisy for the cheapest ones.
- Vanilla and Solid 1.9 finish synchronously inside the click; React 19 and
  Solid 2.0 flush in a microtask; what flushes synchronously at the end of
  `batch()` (create/replace/update/clear) and in a microtask after a bare
  signal write (select/swap/remove/append). Every framework's DOM was verified
  complete at the script stop point; one that deferred to a timer or a later
  frame would fail the run rather than report a short time.
- Headless Chromium; headed numbers differ slightly.
- `what` is built from the repo working tree (not the published npm package).
- All frameworks are bundled by the same vite + esbuild minifier; Solid's
  official entries use rollup + terser, so absolute sizes differ from theirs.
- Implementations follow each framework's official krausest entry idioms
  (React: memo + immutable updates; Solid 1.9: createSelector; Solid 2.0:
  selection store, automatic microtask batching; what: per-row label signals)
  with this harness's shared markup.
