# What Framework 0.13.5

## More reliable reactive interfaces

- Views continue updating when a condition reveals new reactive data.
- Repeated mounting, removal and error recovery no longer leave abandoned updates running in the background.
- Server and client output agree more consistently on fragments, spreads and attributes, and unsupported rendering combinations fail clearly instead of silently dropping content.

## Correct requests and predictable builds

- URLs retain their intended values, including repeated parameters, spaces and equals signs. Cached pages no longer mix up different repeated-value orders.
- Projects with different Vite versions can share the compiler without producing a blank application.
- Failed package builds are reported as failures, so broken output cannot be mistaken for a successful release.

## Upgrade guidance

Applications with persistent ISR stores should clear or rebuild old entries, or let them expire normally, because earlier cache keys could collapse differently ordered repeated query values. No cache is automatically deleted by installing the update.

Fine-grained compiled-JSX server rendering is still a separate upcoming capability. Use the documented VNode/automatic JSX server-rendering path; this release improves diagnostics and correctness without claiming that missing compiler target is complete.

The independent package group advances to 0.13.5. The deprecated `what-mcp` package stays frozen at 0.12.4.
