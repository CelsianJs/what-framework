# What Framework 0.13.11

## Safer pages and package installation

Server-rendered attributes now validate their names before every output path,
including `false` values on data and accessibility attributes. Ordinary valid
attributes retain their existing behavior.

Concurrent ISR requests no longer reuse another request's result when the
render reports `private: true` or `usedRequestHeaders: true`. Waiting requests
render again with their own context. Public renders still share work; private
results remain uncached. Applications must continue to mark private content or
declare the appropriate cache variation: this fix does not automatically infer
every form of personalized content.

`what-server` now declares `what-router` as a required peer. A standalone npm
installation supplies the router needed by the Node entry, rather than relying
on a dependency already installed elsewhere in a workspace.

## Updates stop cleanly and errors remain visible

Disposing a hydrated element now removes its reactive attribute subscriptions,
so subsequent state changes do not continue updating the detached element.

An error-boundary fallback that throws no longer leaves the component context
stack pointing at the failed boundary. Later mounts retain their own context.
Stable effect failures are reported in production while sibling effects and
later updates continue to run.

DevTools now record an effect's first execution and dependencies immediately,
without rerunning the callback. Lazy computed values stay unevaluated until
read, and their first evaluation is counted once.

## More useful development feedback

Editing an imported component now updates the visible app without a manual
refresh. If no component-replacement runtime is installed, the Vite plugin
reloads the page. This fallback resets local component state; it is not
state-preserving hot replacement. An installed replacement hook still owns its
updates.

The recommended ESLint configuration warns about destructuring props during
native component setup. Native components run once, so destructuring can freeze
a value before reactive tracking begins. Read `props.value` inside a reactive
callback instead. React compatibility components are excluded. Projects that
select rules individually can enable `what/no-destructured-props` explicitly.

TypeScript examples and generated-project guidance now describe reactive prop
reads and tracked bindings consistently.

## Verification before and after publishing

Local release verification and the publisher use the same ordered correctness
gates, including declaration/runtime parity, error catalogue and generated-doc
checks, typechecks and lint. Local benchmarks remain blocking; CI keeps its
separate non-blocking performance signal.

The publisher rejects non-`main` workflow refs. It completes missing package
versions before reconciling the requested tag for versions already on npm,
and stops on failed registry probes or tag writes. Post-publish verification
checks the exact version and requested tag for every maintained package, then
installs pinned versions and exercises the published packages. npm cohort and
tag updates are not atomic; a failed run must be completed and verified before
the release is considered finished.

CI also runs a bounded native WebKit acceptance check for hydration, controlled
inputs, radio selection, events, SVG and visible islands. A separate packed
consumer verifies standalone server installation. These are additional
regression checks, not exhaustive browser or deployment certification.

## Migration and scope

- Keep personalized pages private or vary their cache key appropriately.
- Expect a page reload, and local state reset, for component edits without an
  installed replacement runtime.
- Prefer reactive property reads over setup-time prop destructuring when the
  new lint warning identifies a captured value.
- npm installs the now-required router peer for standalone `what-server` use.

This patch adds no runtime dependencies, changes no public Node engine minimum,
and does not introduce a new rendering API, CommonJS output or performance
improvement claim. The maintained fixed-version group contains 13 packages;
deprecated `what-mcp` remains frozen at 0.12.4.
