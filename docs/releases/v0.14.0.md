# What Framework 0.14.0

## Deploy a full-stack What app to Vura

`what-server` (also `what-framework/server` under Node) adds a Vura adapter.

- `createVuraHandler(optionsOrHandler)` returns the Function module Vura loads,
  `{ fetch(request, env) }`. It takes `createRequestHandler` options or an
  existing handler, and rebuilds `request.url` from `x-forwarded-host` and
  `x-forwarded-proto`, ignoring malformed values.
- `buildVuraOutput({ projectRoot, outDir, entry, staticFiles, memory })` writes
  `dist/static/**`, one esbuild bundle at `dist/functions/_/index.js`, and a v1
  `dist/manifest.json` with one `/*` serverless route. Its required features
  are `api` and `function-compute`, so the deploy needs no dedicated compute.
  The manifest sets `"filesystemFirst": true`, which tells the Vura edge to
  serve files from `dist/static` before the catch-all Function. esbuild is
  resolved from the project and is never a runtime dependency.

`create-what --template=fullstack` now has `npm run build`, which writes that
output from the same `createHandler()` that `npm start` runs.

## Limits

- The ISR cache inside a Function is per instance. Pass a shared what-isr store
  for one cache across instances.
- The what-isr poll scheduler does not run inside a Function. Schedule
  revalidation with an external cron that calls `POST /__what_revalidate`.
- Static-first routing for this manifest needs vura-platform's edge support
  for `filesystemFirst`.

## Behaviour changes in the full-stack template

- Production without `WHAT_REVALIDATE_SECRET` logs one warning and does not
  mount the revalidate webhook (`POST /__what_revalidate` returns 404). It used
  to exit at startup.
- The dev server serves framework sources only from
  `/node_modules/what-framework/src/` and `/node_modules/what-core/src/`.
- `what.config.js` no longer claims that `what build` or `what start` read it.
