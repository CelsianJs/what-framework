# What Framework 0.15.0

0.15 keeps React's familiar names and call shapes and puts an entirely new
engine underneath them. It is a breaking release: upgrade every What package
together, recompile, and follow [UPGRADING.md](../UPGRADING.md). The full list
of changes is in [CHANGELOG.md](../../CHANGELOG.md).

## The engine

- A push-pull signal engine with an owner tree. Components run once; an
  effect owns what its run creates, and a component owns everything it
  creates.
- Async values in the graph. A `computed()` that returns a promise fetches,
  aborts a superseded run and keeps its last value meanwhile. `<Suspense>`,
  `startTransition`/`useTransition`, `useOptimistic`, `use()` and `settled()`
  read it, with React's API shapes.
- Development code is compiled out of production builds. what-core,
  what-router and what-server export a production tier, a bundler tier and
  their source, by export condition.

## Server and hydration

- A compiled server target, buffered and out-of-order streaming, and a
  response a render can set its status, headers and redirect on.
- Hydration by adoption: matching server markup creates no nodes and is not
  fetched again. A mismatch is reported as a structured record, only the
  differing part is rendered on the client, and the page ends up holding what
  a client render would. Development also reports each attribute hydration
  had to rewrite.

## Data, actions and routing

- `query()` and one query cache under `useQuery`, `useSWR`,
  `useInfiniteQuery` and `useFetch`.
- React 19's `useActionState` and `useFormStatus`. Server actions run as
  transitions and revalidate inside them. CSRF is checked by Fetch Metadata and
  `Origin`, so forms on cached pages post without a token.
- Navigations are transitions that prepare the destination before they commit.
- A route layout stays mounted, with its state, while the visitor moves
  between the routes that share it, and when the params or the query
  change: its `params` and `query` are live.

## Tools for agents

- One coded diagnostics channel and a catalogue of 79 codes, each with a fix
  and an example ([ERRORS.md](../ERRORS.md)).
- The compiler reports state a component reads once in its body
  (`ERR_STATE_READ_ONCE`), and its findings reach the page in development:
  the console, `getDiagnostics()` and the MCP tools show them with their
  source location.
- 25 MCP tools, including `what_why` and `what_events`.
- eslint-plugin-what rewrites the moved imports (`eslint --fix`), reports
  state stored or sent as a value (`setSubmitted({ name })`,
  `JSON.stringify(user)`), and runs the compiler's read-once checks on code
  the compiler does not build. The repo's example apps and sites are linted
  with these correctness rules.
- The create-what scaffold's `npm run lint` parses TypeScript and reports
  unused variables.

## Before you upgrade

- The root entry went from 177 names to 58; the kits moved to subpaths.
- The server and the client must run the same release: the hydration
  protocol changed.
- `onChange` on a text field fires on each keystroke, as React's does, and
  `useEffect` and `onMount` run children first, as React's do. Validation
  that ran when the user left a field moves to `onBlur`.
- Every behaviour change, with its migration, is in
  [UPGRADING.md](../UPGRADING.md#behaviour-changes).

## Known issues

What still differs from React or is unfinished in 0.15.0, the most likely
first in each group. The app smoke suite passes in Chromium, WebKit and
Firefox, and CI runs it in all three; in WebKit and Firefox the heap checks
are skipped, because only Chromium lets a test force a garbage collection.
[MIXED.md, Limits](../../packages/react-compat/MIXED.md#limits) and
[REACT-COMPAT.md, Known limitations](../../REACT-COMPAT.md#known-limitations)
have the full list, with the rarer cases left out here.

### what-react

- **Hidden Suspense content keeps its refs and layout effects.** Content that
  suspends after it was shown stays mounted and hidden with its state, but
  its refs and layout effects stay attached; React detaches them while it is
  hidden and runs them again when it shows. When a boundary catches an error
  or content suspends, siblings in the same commit can set up their refs and
  effects before the fallback replaces them, and are cleaned up then; React
  sets none of them up. *Who:* `<Suspense>` around lazy panels or tabs, error
  boundaries around lists that fill in later. *Workaround:* let a layout
  effect that measures allow for a hidden, zero-size element, and keep
  effects safe to set up and clean up at once, as React's `StrictMode`
  already asks.
- **React elements that native code places are rebuilt in some builds.** A
  keyed list of React elements a native component places itself (not a React
  tag) keeps its rows in a client build. In a page that hydrates, or an app
  whose native code uses `h()` or renders a native component inside a React
  tree, a row is built again when its props change, a moved row loses the
  focus, and an unkeyed list is built again on every change. Hydration also
  builds again the React elements a native component places (its
  `children`, a slot prop), losing focus and typed text there.
  *Who:* server-rendered mixed apps that hand React elements to native
  components. *Workaround:* render the list or the slot inside a React
  component.
- **A component made by calling a library belongs in a React file.** A
  component is React code where it is written, not where it is used:
  `styled.button` or `styled('span')(…)`, a component handed to a React
  package as a prop (`components={{ a: Link }}`), and JSX handed to one from
  outside a React tag (`toast.custom(() => <b>…</b>)` in a native handler)
  are not React when written in a native file. *Who:* mixed apps using
  styled-components or Emotion, react-markdown, virtual lists, toasts.
  *Workaround:* write them in a React file and import them; a render prop
  written inside a React tag's props needs nothing.
- **Rendering is synchronous.** There is no time slicing: a transition does
  not keep the old screen while new content suspends (the fallback shows),
  `useDeferredValue` returns the value it was given, and `isPending` is true
  only while an async action runs. *Who:* apps that use `startTransition` to
  avoid a fallback on navigation or a tab change. *Workaround:* put the
  `<Suspense>` closer to what loads, with a fallback of its size.
- **Some React packages are unsupported:** renderers built on
  `react-reconciler` (react-three-fiber, react-konva, ink,
  @react-pdf/renderer), React Server Components and what needs them (the
  Next.js app router), `react-dom/server`, and packages that read React's
  internals (fibers, DevTools hooks). *Who:* 3D, canvas and PDF apps, Next.js
  apps. *Workaround:* none; keep them on React.
- **what-react alone does not server-render.** In full compat (every file a
  React file) `renderToString` is not provided, and `hydrateRoot` renders in
  the browser in place of the server's HTML, inside the call, so its first
  commit cannot reach the root it returns. *Who:* server-rendered React apps
  moved to what-react whole. *Workaround:* mixed mode, where React islands
  render on the server and hydrate by adopting its HTML.
- **`useId` is numbered in render order**, not by tree position: a component
  that renders on one side only, with a `useId` and no node, shifts the ids
  after it, and a mismatch is reported. *Who:* islands that render a
  client-only component (a `typeof window` check) before a Radix or React
  Aria component. *Workaround:* render the same components on both sides,
  and show client-only content after mount, from state set in `useEffect`.
- **React 19's resource handling is not done.**
  `<link rel="stylesheet" precedence>`, `<style precedence>`, an async
  `<script>`, `<title>` and `<meta>` stay where the island renders them
  (React moves them to the head), no image preload is written, react-dom's
  `preload` and `preinit` do nothing, and `Profiler` measures nothing. *Who:* React 19 code that renders
  its metadata or stylesheets in components. *Workaround:* put head tags in
  What's `<Head>` and load stylesheets from the entry.
- **A native component in a React tree is rebuilt for a new prop.** When its
  React parent passes a prop it did not pass on the first render, it is built
  again and loses its state (development warns). *Who:* React components
  that pass optional props to native children. *Workaround:* pass every prop
  from the first render, `undefined` if need be.
- **A React tag draws as SVG only under an `<svg>` in the same file.** A
  React component that renders bare `<g>` or `<path>`, placed in an `<svg>`
  written in another file or rendered by a native component, gets HTML
  elements that do not draw. *Who:* icon and chart parts. *Workaround:* write
  the `<svg>` in the file that uses the React tag, or let the component
  render its own.
- **Events are listeners on their elements, not delegated to the root.**
  `stopPropagation()` in a React handler also stops native listeners above
  it, including a library's click-away listener on the element it portals
  into; `onMouseEnter` and `onMouseLeave` do not cross portals; `onWheel` and
  the touch events are not passive; a checkbox's `onChange` fires on the
  native `change`, not during the `click`. *Who:* popovers with click-away
  handling, tests that dispatch events by hand. *Workaround:* none in
  general.
- **`StrictMode` does nothing**: no double render and no second run of
  effects in development, so a missing effect cleanup goes unseen. *Who:*
  teams that rely on it to check effects. *Workaround:* run the tests on
  React too.
- **`<Activity mode="hidden">` unmounts its tree**, losing its state; React
  keeps it. *Who:* tabs or offscreen panels built on `Activity`.
  *Workaround:* keep the panel mounted and hide it with CSS.
- **A form submitted before hydration is lost under a strict CSP.** A form
  whose `action` is a function is guarded (it does not navigate or put its
  fields in the URL), but where a Content Security Policy refuses inline
  scripts the capture script does not run (what-react writes no nonce), so
  the submission is dropped instead of replayed. *Who:* server-rendered apps
  with form actions and a strict CSP. *Workaround:* disable the submit
  button until the island has hydrated.
- **Code that reads the page during a commit can see a different moment from
  React's.** A class's `getSnapshotBeforeUpdate` sees the new props and text
  of elements patched earlier in the same commit (and a controlled
  checkbox's new `checked`), where React's sees none of the commit's changes.
  A custom element's `connectedCallback` can see rows the commit is
  removing. *Who:* classes that measure scroll before an
  update, form-associated custom elements in React lists. *Workaround:*
  none.

### Native What

- **A component reads the branch it returns once.** Components run once, so
  `function Badge({ value }) { return value ? <i>{value}</i> : null }` (or
  the same with `h()`) keeps the branch it took first: the text updates, but
  clearing `value` leaves an empty `<i>`. Development reports
  `ERR_PROP_READ_ONCE` with the fix. *Who:* code written the React way, with
  an early `return null`. *Workaround:* put the condition inside the JSX
  (`<>{value ? <i>{value}</i> : null}</>`), or use `<Show when={value}>`.
- **A JSX helper imported from another module keeps a prop's first value,
  with no warning.** `function Helper({ value }) { return mk({ value }) }`,
  where `mk` renders JSX, shows the first `value` forever. With `mk` in the
  same module development reports `ERR_PROP_READ_ONCE`; imported, nothing is
  reported. *Who:* code that builds markup with shared helper functions.
  *Workaround:* render the helper as a component (`<Mk value={value} />`), or
  hand it `props` and read `props.value` in it.
- **A `useEffect` cleanup reads the prop's new value.**
  `useEffect(() => { join(roomId); return () => leave(roomId); })` leaves the
  new room when `roomId` changes, never the old one: a component runs once,
  so the cleanup reads the prop as it is when it runs, where React's sees the
  value of the render that made it; development reports
  `ERR_CLEANUP_READS_LIVE` for this shape. *Who:* effects ported from React that
  subscribe by a prop or a signal and unsubscribe in the cleanup.
  *Workaround:* keep the value in a local inside the effect
  (`const room = roomId`) and use it in both places
  ([GOTCHAS.md, section 27](../GOTCHAS.md)).
- **A static `xlinkHref` in compiled SVG does not link.**
  `<use xlinkHref="#icon" />` written as a constant is written as an
  attribute the browser ignores, so the icon does not draw; a dynamic one, or
  one through a spread, is written in the XLink namespace. *Who:* icon
  sprites written the React way. *Workaround:* write `href` (or
  `xlink:href`).
- **In WebKit, a Vite chunk whose download failed does not download
  again.** `lazy()` asks for it again on the next visit and on the error
  boundary's reset, but Vite preloads a chunk that has imports of its own
  with `<link rel="modulepreload">`, and once that failed WebKit fails every
  `import()` of it with no request, in the page and after a reload (measured
  in Playwright's WebKit; Chromium and Firefox request it again). *Who:*
  code-split Vite apps in Safari on flaky networks. *Workaround:*
  `build: { modulePreload: false }` in `vite.config.js`: WebKit then
  downloads the chunk again, though a chunk's own imports download after it
  instead of beside it.

- **ISR regeneration below a base path renders the fallback.**
  `cache.revalidatePath('/about', { regenerate: true })` renders the path
  without the base, so the regenerated entry is the Router's fallback, served
  until the next revalidation. *Who:* ISR apps served below a base.
  *Workaround:* revalidate without `regenerate`, so the next request renders
  the page.

- **An island loses props named `name`, `mode`, `mediaQuery` or
  `component`.** `<Card client:load name="Ada" mode="dark" />` hands `Card`
  `undefined` for both, on the server and in the browser, because the island
  wrapper keeps those names for itself. *Who:* compiled `client:*` islands
  with such props. *Workaround:* rename the prop (`label`, `theme`).

- **Two copies of what-core on one page run each delegated handler twice.**
  A library that bundles its own what-core, beside the app's, makes a click
  (and every other delegated event) run its handler once per copy. *Who:*
  apps on a What component library that bundles what-core. *Workaround:* the
  library lists what-framework as a peer dependency instead of bundling it,
  and the app keeps one copy (Vite's `resolve.dedupe`).

### Tooling

- **Every saved edit reloads the page in development.** There is no hot
  replacement yet: an edit to a native file or a React file reloads the page
  and its state is lost. *Who:* everyone using the dev server.
  *Workaround:* none yet.
- **A React `.tsx` file needs `/** @jsxImportSource react */`.**
  `tsconfig.json` has one `jsxImportSource`, What's, so without the pragma
  TypeScript checks a React component's refs, `style` objects, event
  handlers and `children` against What's types and reports errors. The dev
  server names a file that lacks it. *Who:* TypeScript apps with React
  files. *Workaround:* start each React `.tsx` file with the pragma, as the
  scaffold's does, and install `@types/react` and `@types/react-dom`.
- **A build without Vite must import `what-react/hydrate-islands`** before
  `hydrate()`; what-react's Vite plugin adds it. Without it an esbuild,
  Rollup or webpack production page replaces each island's server HTML: a
  focused input loses its node and its focus, with no warning (development
  warns and names the import). *Who:* server-rendered mixed apps built with
  another bundler. *Workaround:* add the import to the entry.
- **JSX that a dependency publishes stops the build with the bundler's own
  error.** The Vite plugin never compiles a file under `node_modules`, so a
  package that ships uncompiled JSX or TSX, or a linked library with
  `resolve.preserveSymlinks: true`, fails with a parser message ("Unexpected
  JSX expression") that names neither the rule nor its option. *Who:* apps
  that use a What component library as source. *Workaround:*
  `what({ compileDependencies: /my-lib/ })`.
