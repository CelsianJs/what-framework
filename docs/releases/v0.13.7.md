# What Framework 0.13.7

This patch corrects public TypeScript declarations to match existing rendering
and router behavior. It was found while enabling strict checking in a real
downstream dashboard; the fixes belong in What, not consumer type overrides.

## Reactive components and attributes

Components may return renderable children, including reactive functions, arrays,
text and empty values. JSX still validates component props and rejects arbitrary
objects and promises. Optional reactive DOM attributes may return null or
undefined, matching the runtime's attribute-removal behavior.

The JSX contract uses TypeScript's `JSX.ElementType` support (TypeScript 5.1+).
The downstream dashboard is checked with its own pinned TypeScript toolchain,
in addition to this repository's declaration and runtime-parity tests.

## Synchronous middleware contract

Route middleware receives `{ path, params, query, route }` and runs synchronously:

- `true` or no return value: continue.
- `false`: render the router fallback or access-denied view.
- A string: redirect to that path.

The previous declarations incorrectly permitted promises. The runtime never
awaited them, so an asynchronous middleware check was not a reliable guard.
This release rejects that usage in TypeScript; it does not add runtime
enforcement for JavaScript callers.

Use an async guard as a **component wrapper**, not an entry in `middleware[]`:

```ts
import { asyncGuard } from 'what-router';

const ProtectedPage = asyncGuard(
  async () => await checkAccess(),
  { fallback: '/login' },
)(AccountPage);

const routes = [{ path: '/account', component: ProtectedPage }];
```

Client-side routing is not a server authorization boundary. Protect private
data and mutations in the server/API as well.

## Release scope

The maintained fixed-version group contains 13 packages; deprecated `what-mcp`
remains frozen at 0.12.4. There are no new runtime dependencies or rendering
capabilities, and these declaration changes do not establish a new performance
claim.
